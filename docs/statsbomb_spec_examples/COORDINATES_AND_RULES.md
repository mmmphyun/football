# StatsBomb 좌표계 & 도메인 분석 규칙 상세

## 1. 좌표계 상세 (Coordinate System)

* **피치 규격**: $120.0 \times 80.0$ (단위: 미터/야드 환산 표준)
  - $x$ 축: $0.0 \sim 120.0$ ($0$: 우리팀 골라인, $120$: 상대팀 골라인)
  - $y$ 축: $0.0 \sim 80.0$ ($0$: 경기장 상단 터치라인, $80$: 경기장 하단 터치라인)
  - 골대 위치: $x=0, y=40$ (자책 골대), $x=120, y=40$ (상대 골대)
  - 페널티 박스: $x \le 18$ 및 $x \ge 102$ ($y: 18 \sim 62$)

```
 (0,0)                                              (120,0)
   ┌──────────────────────────────────────────────────┐
   │                                                  │
   │  ┌──────┐                             ┌──────┐  │
   │  │ (18) │                             │(102) │  │
   │──┤      │             (60,40)         │      ├──│
(0,40)│  (0) │                +            │(120) │  │ (120,40)
[우리골]┤      │                             │      ├──┤ [상대골]
   │──┤      │                             │      ├──│
   │  │      │                             │      │  │
   │  └──────┘                             └──────┘  │
   │                                                  │
   └──────────────────────────────────────────────────┘
 (0,80)                                             (120,80)
```

> **[중요] 절대 공격 방향을 반전하지 마세요!**
> StatsBomb 데이터는 모든 팀의 모든 이벤트가 **항상 왼쪽($x=0$)에서 오른쪽($x=120$)으로 공격**하도록 전처리되어 제공됩니다.

## 2. 3분할(Thirds) 구역 정의

* **Defensive Third (수비 3분할)**: $0.0 \le x < 40.0$
* **Middle Third (중원 3분할)**: $40.0 \le x < 80.0$
* **Final Third / Attacking Third (공격 3분할)**: $80.0 \le x \le 120.0$

---

## 3. 12x8 바둑판 그리드 (Grid Zones)

* 가로 12칸 (1칸당 $10.0\text{m}$), 세로 8칸 (1칸당 $10.0\text{m}$)
* `col = min(11, max(0, int(x * 12 / 120)))`
* `row = min(7, max(0, int(y * 8 / 80)))`
* 팀별/소유 상태별(`possession`, `out_of_possession`) 점유 비율 집계:
  $$\text{Cell Occupancy} = \frac{\text{해당 셀에 위치한 선수 스냅샷 수}}{\text{해당 팀/상태의 전체 선수 위치 수}}$$

---

## 4. 경기 시간(Time) 계산 규칙

* `minute`와 `second`가 이미 1분/1초 단위 경기 누적 시간을 나타냅니다.
* 전반전(`period=1`): `0:00` ~ `45:00` (+ 추가시간)
* 후반전(`period=2`): `45:00` ~ `90:00` (+ 추가시간)
* **경기 총 소요 시간(분)**:
  $$\text{duration\_min} = \max(\text{events.minute}) \approx 90 \sim 100\text{분}$$
  *(기존 코드처럼 `(period - 1) * 3600` 오프셋을 더하면 후반전에 60분이 중복 가산되어 150분이 되므로 절대 금지)*

## 5. 360 프리즈프레임 익명성 처리 전략

360 데이터에는 선수 ID가 없습니다. 따라서 시스템은 다음과 같은 하이브리드 전략을 사용합니다:

| 분석 대상 | 360 데이터 활용 방식 |
| :--- | :--- |
| **포메이션 (Formation)** | 선수 개별 평균 위치는 **이벤트 참여 위치(ID 명시)**를 기본으로 하고, 360 프레임은 팀 전체 무게중심에 반영 |
| **그리드 점유 (Zones)** | `teammate` 플래그를 이용해 아군/상대팀으로 분류하여 그리드에 카운트 가산 |
| **하이라이트 플레이어** | `actor=True` 선수는 해당 이벤트의 `player_id`로 매핑하고, `keeper=True`는 골키퍼로, 나머지 선수는 번호 없는 팀 토큰/고스트로 렌더링 |
| **움직임 예측 (Predict)** | 클립 윈도우 내 연속 이벤트 프레임 위치 기반으로 속도 $\to$ $+2$초 외삽(고스트 렌더링) |
